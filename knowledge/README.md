# Knowledge bundle

A generated map of this repository in [Open Knowledge Format v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md):
what each part of the audit harness does, why it is shaped that way, and the traps a newcomer
would otherwise find the hard way.

- **Start here:** [architecture/overview.md](architecture/overview.md)
- **Everything:** [index.md](index.md)

15 concepts, generated by catalogify 0.9.0 from commit `e8c542a`.

## Checking it

`catalogify verify knowledge/` resolves every cited commit, every symbol in an `# Interfaces`
table, and every source path against the repository. `catalogify validate knowledge/` checks
conformance with the format.

## Correcting it

Where the code and its git history did not settle a fact, the concept says so in an
`open_questions` list in its frontmatter instead of guessing. There are 18 such questions across
11 concepts: things like whether a limit is deliberate, or whether an old file is retired.

**Answering them is the most useful thing a reader can do here, and the one part a machine
cannot.** Run the catalogify *clarify* workflow to be walked through them. Each answer is written
into the concept with a `<!-- clarified: ... -->` marker and survives every later regeneration.
